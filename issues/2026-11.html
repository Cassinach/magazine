Editorial

巻頭言

創刊号です。この雑誌は、Web のフルスタック開発と三次元再構成を行き来する一人の読者のために、Claude が毎月 Web を調べて編集します。「最近アンテナが鈍っている」という感覚を、1 冊読めば取り戻せることが目標です。

2026 年 8 月から 11 月にかけての空気を一言でいえば、「前提が入れ替わった秋」でした。TypeScript は Go 製が当たり前になり、Vite 8 と Node 22 を要求しないフレームワークはほぼ消え、pnpm は Rust 製になり、Claude のモデルは 3 週間で総入れ替え、three.js には Gaussian Splat がコアで入りました。どれも単体では「アップデート」ですが、まとめて見ると開発環境の地面が一段高くなっています。

一方で、便利になった分だけ攻撃面も増えました。巻頭特集では、正規の署名が付いたまま公開された npm のマルウェアと、それに先回りして「既定で守る」方向に舵を切ったパッケージマネージャーの話を扱います。セキュリティ欄の Next.js / React の Critical RCE 3 連発や、MCP SDK と Claude Code の High 連発も、同じ文脈で読んでいただけると思います。

なお本号の調査環境は GitHub・npm・PyPI・nodejs.org・anthropic.com 以外のサイトに直接アクセスできず、arXiv や各社ブログの内容は検索結果から確認したものが含まれます。該当箇所は本文で明示しました。右から左へ、どうぞ。

署名付きでも汚染される——tensorlake 事件と、既定で守るパッケージマネージャー

影響大 npmpnpmTrusted PublishingprovenanceGitHub Actions

10 月 8 日、npm の tensorlake 0.5.144 は正規ワークフローから Sigstore provenance 付きで公開された悪性版でした。provenance は「どこから出たか」しか証明しません。同じ秋、pnpm 11/12 と npm 12 は公開直後のバージョンを待つ設定と install スクリプトのブロックを既定にしました。今週やるべき 3 つの設定を示します。

何が起きたか

10 月 7 日、npm パッケージ tensorlake のリポジトリに、管理者権限を持つアカウントから GitHub の Web UI 経由で main へ直接 push がありました。コミットは「Add files via upload」が 5 回、「Add preinstall script to package.json」、「bump version to 0.5.144」と続き、TypeScript SDK に lib/setup.mjs と preinstall フックが足されています[2]。翌 8 日 01:12 UTC、悪性版 0.5.144 が 正規の公開ワークフローの手動実行で公開されました。つまり Sigstore の provenance が付いた、署名として完全に正しいマルウェアです[1][3]。npm は約 3 時間後の 04:15 UTC に 0.0.1-security のプレースホルダ版を公開して封じました。

同日、メンテナは PR #1016 で最後のクリーンなコミットまで全戻しし、CI を npm ci --ignore-scripts に変え、install スクリプトの混入を検知するトリップワイヤを足し、main への直接 push と管理者バイパスを禁止し、npm 公開環境に 2 人承認を導入し、鍵をローテーションし、6 つのネイティブパッケージを unpublish しました。クリーン版 0.5.145 は同日 20:24 UTC、以後はスコープ付きの @tensorlakeai/tensorlake に移行しています[1]。ペイロードの挙動（トークンや AI エージェントの設定ファイルの窃取、自己複製）はセキュリティ企業の報道のみで、編集部では一次確認できていません。

なぜ重要か

この事件は「provenance を検証すれば安全」という前提を正面から壊しました。provenance が証明するのは「このリポジトリのこのワークフローから出た」ことだけで、ワークフローを起動した人間が正当かどうかは証明しません。GitHub Advisory Database に登録されたマルウェアは 11 月 9 日時点で npm 109,815 件、PyPI 11,971 件で、11 月 6〜9 日だけでも双方に 25 件以上が追加されています。

防御は「既定」に移った

同じ秋に、パッケージマネージャー側の防御は「設定すれば使える」から「既定で有効」に変わりました。

Next.js 16.4、Cache Components が標準路線に——ただし脆弱性も集中

影響大 Next.jsCache ComponentsTurbopack

16.4 で Partial Prefetching が安定化し、create-next-app は Cache Components を既定で有効にします。一方で 10 月の Critical RCE 2 件と 11 月 3 日の Moderate 7 件の大半が use cache まわりでした。self-hosted は 16.4.5 以上が必須です。

何が起きたか

Next.js 16.4.0 は 10 月 6 日に出ました[10]。目玉は Partial Prefetching の安定化です。navigation() と prefetch() から unstable_ が外れ、ensureStatic は "shell" / "prefetch" / "navigation" の 3 段階で安定化しました。内部的には Cache Components が PPR（Partial Prerendering）のシグナルとなり、旧 PPR のコードパスは削除されています。create-next-app は Cache Components を既定で有効にするようになりました。

ほかに Turbopack のエクスポート名マングリングと共有ランタイムがビルドで既定 on、next analyze が experimental から昇格してルート別サマリーと比較ビューを備え、エージェントにアップグレード手順を渡す next upgrade --ai が追加されました。React 19.3 の browser() を使った「browser bailouts」が CSR bailout エラーを置き換え、Pages Router の React 18 サポートは非推奨になっています。ルートマッチングは strict が既定になり、どのルートにも一致しない app ページはエラーになります[10]。

React 19.3：View Transitions と Fragment Refs が安定版に

影響大 ReactView TransitionsRSC

React 19.3 は破壊的変更なしで <ViewTransition /> と Fragment Refs を安定化しました。React Router は自前の遷移 API を非推奨にして React 側へ寄せています。10 月 14 日の 19.3.1 系パッチは RSC の Critical RCE 修正を含むため、RSC 利用者は先に更新を。

何が起きたか

React 19.3.0 は 9 月 9 日にリリースされました。破壊的変更なしのマイナーで、長く experimental だった 2 つの機能が安定版に入っています[14][15]。

<ViewTransition /> と addTransitionType は、ブラウザの View Transition API を使って要素の enter / exit / move / resize をアニメーションさせます。ルーターが独自に持っていた遷移アニメーション層が不要になり、React Router は 8.5.0（10 月 19 日）で自前の view-transition API を非推奨にして React 側に寄せました[17]。

Fragment Refs は <Fragment> に ref を渡せるようにするもので、ラッパー div を増やさずに兄弟 DOM ノードに対するイベント登録・フォーカス・Observer・計測・スクロールができます。レイアウト用に挟んでいた div を消せるので、Tailwind 系の UI では地味に効きます。

その他の変更

  • react-dom に browser() が追加され、use(browser()) を Suspense 内で使うとサブツリーをブラウザ専用として扱えます。サーバー API には onBrowserBailout が増えました。
  • Trusted Types API に対応し、CSP の require-trusted-types-for 'script' が使えるようになりました。
  • Server Components の中で <Context> を直接レンダーできます。
  • トランジションが独立してレンダーされ、遅いトランジションが無関係なものをブロックしなくなりました。
  • 条件付き use() に DEV 警告が出ます。

10 月 14 日の 19.3.1 は RSC の transport protocol 改善 1 件ですが、同日に 19.2.9 / 19.1.10 / 19.0.9 も出ており、これは react-server-dom-* の Critical RCE と DoS の修正を含むセキュリティリリースでした[16]。

React 20 は 11 月 9 日時点で npm に存在せず、canary は 19.3.0 系のままです。

読者への影響

ルーターや UI ライブラリの「遷移アニメーション」機能は、今後 React 本体の <ViewTransition> に収斂していきます。新規に書くなら最初から React の API を使い、ライブラリ独自のものは避けるのが安全です。RSC を使っているなら 19.3.1 以上（または各系列の修正版）への更新を先に済ませてください。

その翌日 10 月 29 日には、Node.js 史上初の「アルファ版」となる 27.0.0-alpha.0.0.0 が出ました[36]。V8 は 15.6 に上がり、Math.sumPrecise や Iterator.zip が既定で有効になります。SEMVER-MAJOR の変更としては、OpenSSL 3 以上が必須になりバンドル版は 4.1.0 へ、FIPS プロバイダのビルドは削除、Intel Mac は experimental に格下げ、domain モジュールが runtime deprecation、HTTP の keepAliveTimeout 既定が 65 秒に、req.headers が null プロトタイプになる、といった項目が並びます。ヒープ上限の既定も「物理メモリの半分を 256MB〜4GB にクランプ」に変わり、Buffer のメモリも上限の対象になりました[36]。

10 月 21 日には 26.12.1 / 24.22.1 / 22.23.4 の協調セキュリティリリースがあり、TLS・DNS・Brotli にまたがる 9 件の CVE（High 5 件）が修正されています[37]。まだ 26.12.0 以前や 24.22.0 以前を使っているなら、LTS 入りとは別に今すぐ上げる理由があります。

影響大 Pythonuvpip

何が起きたか

サーバーレスが「普通の HTTP サーバー」を動かす時代に

影響大 AWS LambdaVercelServerless

AWS Lambda Web Functions はポートを listen する通常の Web アプリをそのまま Lambda で動かします。Vercel も Python GA と長時間ワーカー Daemons を発表。関数シグネチャへのロックインは消え、差は課金モデルとバックグラウンド処理に移りました。

何が起きたか

10 月 12 日、AWS は Lambda Web Functions を発表しました。コードがポートを listen する普通の HTTP サーバー（Express でも Hono でも FastAPI でも）を、イベントハンドラに書き換えることなく Lambda にデプロイできる新しい形態です。HTTPS の終端・スケーリング・配信は Lambda が担い、既存の関数は「Lambda Event Functions」と呼び分けられます。提供リージョンは us-east-1 / us-east-2 / us-west-2 / ap-northeast-1（東京）/ eu-west-1 です[62]。報道では起動時ランタイムは Arm64 の Node.js 24、課金はアクティブ CPU 時間、環境あたり最大 128 同時リクエストとされますが、この 3 点は AWS 公式ドキュメントで未確認です[63]。

3 日後の 10 月 15 日、Vercel Ship 2026 では Python が GA になり（FastAPI / Flask / Django を自動検出）、HTTP サーバーを持たずキューや DB から仕事を取りに行く長時間ワーカー「Daemons」がパブリックベータ、Sandbox 用の永続ストレージ「Drives」が GA になりました[64][65]。Vercel の既定コンピュートはすでに Fluid compute で、こちらもアクティブ CPU ベースの課金です。

何が変わったのか

Feed-forward 3DGS は「減らす」競争へ——Anchor3DGS と NRF-GS（NeurIPS 2026）

影響中 3DGSNeurIPS 2026圧縮ECCV 2026

NeurIPS 2026 採択の Anchor3DGS は少数アンカーから局所 Gaussian をデコードして約 1 桁少ない Gaussian 数を、NRF-GS は球面調和を共有 MLP の残差に置き換えて最大 50% 削減を報告しています。符号化側も Gaussian ではなく特徴を送る方向へ。ECCV 2026 の Best Paper は測地 Gaussian でした。

「増やす」から「減らす」へ

NeurIPS 2026（12 月 6〜12 日、シドニー）に向けた feed-forward 3DGS の論文は、品質競争から Gaussian の数を減らす競争に軸足を移しています。本節の論文情報は arXiv ページを直接確認できず、検索結果で複数ソースが一致したものに限って掲載しています。数値はいずれも著者報告です。

  • Anchor3DGS（arXiv 2610.21634、10 月 15 日、NeurIPS 2026）は pose-free の feed-forward 手法で、ピクセル整列の予測を捨て、情報エントロピーに基づいて配置した少数のアンカーから局所 Gaussian をデコードします。SOTA 品質を約 1 桁少ない Gaussian 数で達成すると報告されています[91]。
  • NRF-GS（arXiv 2609.37115、NeurIPS 2026 ポスター）は splat ごとの球面調和係数を、視線方向・距離・特徴から残差を返す共有の軽量 MLP に置き換え、最大 50% 少ない Gaussian で同等以上としています[92]。
  • StereoSplat（NeurIPS 2026 ポスター）は合成データ XRStereo のみで学習して実ステレオ動画へ zero-shot で metric スケールの新規視点合成を行います。9 月 29 日の StereoGaussians（arXiv 2609.38592）も凍結ステレオ網と校正済み視差で metric 3DGS を構築する同系統です[95]。

圧縮・符号化

送る側の研究も進みます。Feed-Forward Multi-View Feature Coding for 3DGS（arXiv 2610.20590、10 月 14 日）は Gaussian ではなく多視点特徴をビットストリーム化し、受信側で Gaussian 数を選べる設計です[93]。Codec-Compatible Learned Compression（arXiv 2610.26920、VCIP 2026）は SH マップが支配的なビットを狙い、SplatQ（arXiv 2610.13503、10 月 9 日）は二次選択による interaction-aware pruning を提案しています[94]。

学会カレンダー

ECCV 2026（9 月 8〜12 日、マルメ）の Best Paper は Imperial College の「Heat Kernel Textures — the Geodesic Gaussians That Do Not Splat」（arXiv 2609.07557）で、UV 展開なしにメッシュ面上の異方性熱核を Gaussian の測地的等価物として使う手法でした。SIGGRAPH Asia 2026 は 12 月 1〜4 日にクアラルンプール、3DV 2027（テッサロニキ、2027 年 4 月）は 12 月 2 日に最終通知です。いずれも検索結果ベースの日付で、公式サイトは未確認です。

Glossary

新語辞典

minimumReleaseAge
パッケージマネージャーが「公開から N 分経っていないバージョンを解決しない」設定。pnpm 11 以降は既定 1440 分、Bun は [install] minimumReleaseAge、Yarn は npmMinimalAgeGate。公開直後の悪性版を踏む事故を減らす。
Trusted Publishing
CI（GitHub Actions / GitLab / CircleCI）の OIDC トークンでレジストリに短命トークンを発行させ、長期 API トークンなしで publish する仕組み。npm では新規設定が 2 日以内に初回 publish しないと失効する。
staged publishing
npm が公開前にステージ領域へ置き、別の承認を経て公開する二段階リリース（npm stage publish）。2026 年 9 月 3 日以降の複数パブリッシャー設定では既定。
security holding package
npm がマルウェアを削除した後に同名で公開するプレースホルダ版（例: tensorlake@0.0.1-security）。この版名を見たら過去に汚染があったサイン。
workflow dependency lockfile（actions.lock）
GitHub Actions の全依存アクション（推移的含む）を commit SHA とリポジトリ ID で固定する .github/workflows/actions.lock。gh actions-lock で生成し、SHA ピン留めの上位互換とされる。
TOCTOU
Time-of-check to time-of-use。検査した時点と使用する時点の間に対象（パスや symlink）を差し替えられる競合。2026 年 10 月の Claude Code の High 2 件がこれ。
Cache Components / Partial Prefetching
Next.js 16 系のキャッシュモデル。use cache でコンポーネント単位にキャッシュし、16.4 で安定化した Partial Prefetching が静的シェルの事前取得を制御する。11 月の脆弱性 7 件中 5 件がこの周辺。
Lambda Web Functions
AWS Lambda の新形態。ポートを listen する通常の HTTP サーバーをイベントハンドラに書き換えずにデプロイできる。従来の関数は Lambda Event Functions と呼ばれる。
Multi Round-Trip Requests（MRTR）
MCP 2026-07-28 版で、サーバー起点の sampling / roots / elicitation を置き換えた仕組み。ステートレス化に伴い、1 リクエストの中で複数往復を表現する。
Agent Skills
SKILL.md と任意の scripts / references / assets でエージェントに手順を渡す仕様。2026 年 10 月に Anthropic が Agentic AI Foundation（Linux Foundation 配下）へ寄贈。
SPZ v4
Niantic の 3DGS 圧縮フォーマットの第 4 版。gzip から ZSTD に変わり、属性ストリームを独立並列圧縮する。three.js、Spark、Babylon.js、Open3D が 2026 年秋に対応。
KHR_gaussian_splatting
glTF に Gaussian Splat を格納する Khronos 拡張。「Complete, Ratified」ステータスで、kernel と colorSpace が必須、球面調和は 3 次まで。
LoMa
COLMAP 4.2 に内蔵された学習ベースの特徴抽出・マッチング（ONNX、LOMA_B / LOMA_B128）。SuperPoint + LightGlue を外部で回す必要がなくなる。
lazy imports（PEP 810）
Python 3.15 の lazy import foo 構文。モジュールスコープの import を初回アクセスまで遅延し、CLI やサーバーレス関数の起動を速くする。
